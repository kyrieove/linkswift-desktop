# Unidownload

粘贴网盘分享链接，程序在后台加载页面并取到直链，推给 aria2、剪贴板或浏览器。aria2 随应用启动，不用自己装。只在登录时打开本机 Chrome。

也能直接粘贴视频网站页面或普通文件直链。视频那一路交给内置的 yt-dlp，解析、下载、音视频合并、提取音频都在它里面跑。

上游是 [hmjz100/LinkSwift](https://github.com/hmjz100/LinkSwift) 这个油猴脚本。桌面版把脚本注入到内置窗口的页面主世界，并补上它需要的 `GM_*` 接口。仓库内部标识（包名 `linkswift-desktop`、`persist:linkswift` 分区、`%APPDATA%\linkswift-desktop` 数据目录、IPC 名）保持不变，所以从 LinkSwift 桌面版升级过来时旧配置、网盘登录态和未完成的下载都还在。

支持夸克网盘、百度网盘、UC 网盘、迅雷云盘。UC 和迅雷的步骤表取自脚本自身的挂载点：自动点不到时窗口会留着让你点一次「下载助手」，直链照样被程序接住。UC 和迅雷驱动仍是实验性实现，界面按驱动能力显示入口，不隐藏它们的边界。

UC 和夸克的下载直链要求登录态，程序会把应用分区里该域名该带的 Cookie 一起交给 aria2；没登录时会明确说「403…要求登录态」并给「登录网盘」。迅雷的凭证存在页面自己的 localStorage 里，所以「需登录」时会直接把窗口开到 `pan.xunlei.com/login`，登录完自动继续，也可以手动点「我已登录，继续」。


## 运行

```
npm install
npm start
```

首次运行会在 `%APPDATA%\linkswift-desktop` 建立用户数据目录，网盘登录态存在那里。这个目录含多网盘凭证，按密码本对待。

数据目录名沿用旧内部标识 `linkswift-desktop` 而不是可见名称，这是有意的：改名会让旧设置、登录态、aria2 会话和续传记录找不到。

## 怎么用

1. 粘贴分享链接。带提取码的链接直接把完整地址贴进来，程序会自己解析。一次可以贴整段分享文案，里面的多条链接会各建一条任务；某一条认不出来只影响那一条。
2. 需要登录、提取码或授权时，程序会弹出窗口让你处理一次。这一类任务单独停在「需你操作一步」，其他任务照常下载。
3. 直链拿到后按设置推给内置 aria2，开始下载。

任务卡上的状态分五种：**下载中**（带速度、连接数、剩余时间）、**已暂停**、**需你操作一步**（卡上直接写要做什么，并给直达按钮）、**已失败**、**已完成**；一条任务里部分文件失败时显示「部分完成 N 失败 / M 完成」。下载中速度归零满 60 秒会标「可能已停滞」，只提示，不自动重试。

下载中可以「暂停」「继续」「取消」。直接关掉软件也不会丢进度：内置 aria2 把会话写在 `%APPDATA%\linkswift-desktop\aria2\session.txt`，下次打开按 GID 找回，没暂停过的任务自动接着下。

## 媒体与直链

除了网盘分享链接，程序还认两种地址。

**视频网站页面**。粘一个 YouTube、B 站之类的页面地址，程序交给内置的 yt-dlp：它负责解析出可下载的流、挑画质、下载、并且用 ffmpeg 把视频流和音频流合并成一个文件。这一路不需要开浏览器页面，除非那个站点要登录。

**普通文件直链**。粘一个以常见文件扩展名结尾的地址就行，用 aria2 下，多线程。

媒体这一路是单连接的，吃不到 aria2 的 16 线程分片。这是 yt-dlp 原生下载器的性质，不是配置问题。

暂停是把 yt-dlp 的进程停掉，`.part` 半成品留在原地；继续是带 `--continue` 重开，yt-dlp 从半成品接着下。取消会把半成品删掉。

站点解析器会失效，这是 yt-dlp 的常态。程序自己管 yt-dlp 的更新：拉发行版、按发行版附带的 `SHA2-256SUMS` 校验、换文件。**不会**用 yt-dlp 自己的 `-U`，上游发行说明明确说过旧版可执行文件有中间人攻击风险。

ffmpeg 不在安装包里。音视频合并、提取音频、嵌封面这些要 ffmpeg，装一个放 PATH 上就能用；没有的话这些功能不可用，其余照常。

需要登录时，程序在自己的窗口里打开那个站点，登录态留在应用的会话里，导出给 yt-dlp 用。网盘那一套浏览器能力，顺手变成了媒体的登录能力。

设置 → 媒体 这一页管媒体这一路：画质（留空由 yt-dlp 自己挑）、提取音频、嵌入封面与元数据、字幕、整个播放列表、ffmpeg 路径、yt-dlp 路径与更新频道。同一页还有「每个来源用哪个引擎」，默认按来源自己定，改掉之后 aria2 就不再是前提。

界面上每一份来源清单都从注册表画。侧栏那六条、来源页、能力表、筛选和计数，都是同一张表，加一种来源只改一处。

## 界面

第三版界面：左侧窄主导航（任务 / 网盘来源 / 设置），任务区上方是搜索、排序和新建，右侧按需滑出任务详情（概览 / 文件 / 活动与诊断）。侧栏列出状态与四个网盘来源的计数，计数来自真实任务。

- 搜索、排序、状态筛选与网盘来源筛选可以组合使用；筛选后没有结果会明确说明是「筛选为空」还是「还没有任务」；归档视图里是第三种文案。
- 勾选多个任务（行内复选框）后出现批量操作条：主列表里是归档 / 删除，归档视图里是恢复 / 删除，另外还有暂停 / 继续 / 取消。只对符合条件的任务执行，部分失败会单独报出来，不会被整体「成功」提示盖掉。
- 归档：已完成或已失败的任务可以归档，归档后离开主列表，页脚「归档」按钮切到归档视图查看或恢复。主列表最多保留 500 条，更早的自动写进 `jobs-archive.jsonl`。归档不删除任何已下载的文件。
- 失败时任务卡上有诊断块：第几步、要点的目标、一句能执行的建议，以及「复制诊断」「重试」两个按钮。复制的内容含步骤、目标、脚本版本和来源；重试会先重新拉一次上游脚本，拉不到就用缓存版本，并在任务的 detail 里写明「重试使用缓存版本 vX」。
- 快捷键：`Ctrl+K` 聚焦搜索，`N` 新建任务，`Esc` 关闭详情或弹窗。
- 主题在侧栏或设置里切换，浅色 / 深色，选择记在本机渲染进程的 localStorage，不写进设置文件。
- 「已完成」只在确有本地下载进度时表示下载完成；交给剪贴板或浏览器、没有本地字节的任务显示「已投递」，历史任务也不会因为当前设置被改标成别的出口。

应用图标与标志的矢量源、位图和重建命令见 [`resources/brand/README.md`](resources/brand/README.md)。

## 设置

下载器可选「内置 aria2」（默认，随软件启动，只监听 127.0.0.1）和「外部 aria2 RPC」（填你自己 aria2 / Motrix 的地址与令牌，可测试连接）。下载目录留空即 `下载\LinkSwift`。

「允许自动转存」是百度与迅雷共用的全局授权，默认关闭。开启后，百度超过 50MB 的文件会先在你的百度网盘里存一份，迅雷分享也会先转存到「我的云盘」，再把窗口切到网盘助手让你点一次取链；这会往你自己的网盘里写文件。

设置 → 网盘能力 是一张四行表：每个网盘一行，写出能力等级（取自 `DESIGN.md` 已核实的结论）和本机最近一次真实结果，只有本机真跑过才写结果，没有记录就是「未验证」，不会拿猜测填空。同一页还有归档管理：当前归档条数与「清空归档列表」，清空只删记录，不删下载好的文件。

## 上游脚本

启动时从 GitHub 拉取最新版本，成功就缓存。拉取失败依次退回上次缓存和 `resources/userscript.user.js`。

「重新取链」先重新拉一次上游脚本再重建任务，所以「上游改版」这类失败不会拿同一份旧脚本原样重跑一遍；拉不到时用缓存版本，并在任务 detail 里注明用的是哪一版。每条任务都记着它跑的 `scriptVersion` 与 `scriptOrigin`（`upstream` / `cache` / `bundled`），详情和「复制诊断」都会带上。

更新仓库内的固定版本用：

```
npm run fetch-userscript
```

注入前会对脚本打一处最小补丁：迅雷刷新凭证要用的 `config.$xunlei.api.getAccessToken` 上游没有定义，`src/main/userscript.js` 补上它指向的地址。

## 验证

探针都可复跑。

```
npm run check             # 一次跑完下面的语法检查、全部检查与 UI 探针
npm run check:share-link  # 链接与分享文案解析（四种网盘）、批量粘贴与去重
npm run check:aria2       # aria2.addUri 的选项构造
npm run check:job         # 任务状态机：多文件合并、大文件转存、登录过期、链接失效、手动兜底、停滞、重试拉新脚本
npm run check:source-parse # 来源判定：四种网盘、视频页面、普通文件直链、混合粘贴
npm run check:media-settings # 媒体设置：存盘再读回来，以及它变成 yt-dlp 参数
npm run check:ytdlp-args  # yt-dlp 命令行：固定参数、危险开关一个都不能有、输出名与路径转义
npm run check:ytdlp-progress # yt-dlp 进度解析：真实输出行、NA 的处理、Windows 路径不被转义
npm run check:ytdlp-errors # yt-dlp 报错分类：登录、地域限制、画质、限流、ffmpeg 缺失、网络
npm run check:ytdlp-lifecycle # 真实 yt-dlp：下载 → 暂停 → 续传 → 字节一致（本地慢速 HTTP 服务，不联网）
npm run check:lifecycle   # 真实 aria2：暂停 → 退出 → 重启接着下 → 字节一致（本地慢速 HTTP 服务，不联网）
npm run check:archive     # 500 条上限、归档文件格式、旧记录兼容
npm run check:provider-health # 网盘能力表：只留最近一条，文件损坏时退回「未验证」
npm run check:brand       # 品牌资源尺寸/格式与命名兼容性
npm run check:runner      # 检查启动器本身：子进程失败/信号必须让整轮失败
npm run check:negative    # 负例：故意坏的检查、泄漏的探针必须非零退出
npm run probe:boot        # 用本地页面跑通整个注入和驱动链路
npm run probe:ui          # 渲染进程 + preload + IPC 的端到端契约
npm run probe:injection   # document-start 注入时机
npm run probe:throttle    # 隐藏窗口的定时器节流，以及关掉节流后的对照
```

`npm run check` 是唯一入口，任何一步非零退出都不会被包装成成功。`check:lifecycle` 不需要网盘也不需要联网，是「下载一半退出、重开能继续」的回归入口。`probe:boot` 把报告写到 `%TEMP%\linkswift-boot-report.json`，`probe:ui` 写到 `%TEMP%\linkswift-ui-report.json`，截图同为 `%TEMP%\linkswift-probe-*.png`。
